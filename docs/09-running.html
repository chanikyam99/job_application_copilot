Section 09

Running & Debug

Start both servers, verify the API in Swagger, walk through a full end-to-end test, and fix every common error you are likely to hit.

1 Start the Backend

Open a terminal, navigate to the backend/ directory, activate your virtual environment, and run uvicorn:

terminal — backend bash 
# Navigate to backend directory
cd job-copilot/backend

# Activate the virtual environment
# macOS / Linux:
source venv/bin/activate
# Windows:
venv\Scripts\activate

# Start the development server with auto-reload
uvicorn main:app --reload --port 8000

You should see output like this in your terminal:

expected output text 
INFO:     Will watch for changes in these directories: ['/path/to/backend']
INFO:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)
INFO:     Started reloader process [12345] using WatchFiles
INFO:     Started server process [12346]
INFO:     Waiting for application startup.
INFO:     Application startup complete.
Important

The --reload flag watches for file changes and restarts automatically. It is for development only — never use it in production. Keep this terminal window open throughout your session; closing it stops the backend.

WHY uvicorn instead of python main.py

FastAPI apps are ASGI applications, not WSGI. Uvicorn is an ASGI server — it handles the event loop that makes async/await and concurrent WebSocket connections work. Running python main.py with a plain app.run() would block on every request and kill the parallelism that makes the 15-second generation time possible.

How to authorize in Swagger

  1. Click POST /auth/signup → Try it out → fill in email + password → Execute
  2. Click POST /auth/login → Try it out → same credentials → Execute
  3. Copy the access_token value from the response body
  4. Click the Authorize button (top-right of the page)
  5. In the popup, paste Bearer <your_token> into the Value field → Authorize
  6. All subsequent requests will include the Authorization header automatically
WHY check Swagger before the frontend

Debugging through a browser UI adds two layers of uncertainty: "is the backend broken, or is the fetch call wrong?" Swagger isolates the backend. If Swagger calls work but the frontend doesn't, the problem is in api.js. If Swagger calls fail, the problem is in Python. Never mix the two debugging contexts at once.

3 Start the Frontend

Open a second terminal window (keep the backend running in the first). Navigate to the frontend/ directory and start Python's built-in HTTP server:

terminal — frontend bash 
# In a NEW terminal — do not stop the backend
cd job-copilot/frontend

python -m http.server 3000

You should see:

expected output text 
Serving HTTP on :: port 3000 (http://[::]:3000/) ...

Open http://localhost:3000 in your browser. You should see the login/signup page.

WHY python -m http.server instead of opening the HTML file directly

ES modules (type="module" script tags) are blocked when you open files via the file:// protocol due to CORS restrictions that browsers enforce for security. A local HTTP server serves files over http://localhost, which browsers treat the same as a real website. Python's built-in server is zero-config and ships with every Python installation.

4 Test the Full End-to-End Flow

Walk through these 9 steps in order. Each step tests a distinct part of the system.

1
Create an account

Open http://localhost:3000. Click "Create Account". Enter an email and a password of at least 8 characters. You should be redirected to the dashboard automatically — no separate login step needed.

2
Start a new application

Click "+ New Application". The 3-step wizard opens at the Resume Upload screen.

3
Upload a resume PDF

Drag a text-based PDF onto the drop zone, or click "Browse Files". Important: the PDF must be digitally created (not a scanned photo). The file name should appear below the drop zone and the "Next" button activates.

4
Enter job details

Fill in job title and company. Paste a full job description — copy it directly from a LinkedIn job post or company careers page. The more detailed the JD, the better the agent output. Click "Generate My Kit".

5
Watch the generating screen

Step 3 of the wizard shows an animated progress display. You can watch the backend terminal — you should see Groq API calls logged as each agent runs. The backend runs Agents 2, 3, and 4 in parallel via asyncio.gather(), so total time is ~15–30 seconds regardless of how many agents there are.

6
View the 4 artifact tabs

After generation you land on application.html. Click each tab: Fit Analysis should show a score ring and requirement tags; Resume should show a before/after diff; Cover Letter should be a readable multi-paragraph letter; Interview Prep should list 10 expandable Q&As.

7
Update the application status

Use the status dropdown at the top of the page to change from "Not Applied" to "Applied". A "Saved ✓" confirmation should appear briefly. Return to the dashboard — the card badge should reflect the new status.

8
Download the cover letter

On the Cover Letter tab, click "Download .docx". A file named cover-letter-{id}.docx should appear in your downloads folder. Open it in Word or Google Docs to verify the text is correct and editable.

9
Regenerate a single section

Click the "↺ Regenerate" button on any tab. This calls POST /applications/{id}/regenerate?section=cover_letter (or whichever section). Only that one agent runs again — the other artifacts are untouched. The tab content should update with fresh output in ~10–15 seconds.

5 Common Errors & Fixes

These are the errors you are most likely to hit, in roughly the order you will encounter them.

Error Root Cause Fix
CORS error in browser console Backend is not running, so the browser gets no response and reports a network error as CORS Start uvicorn first. The frontend must always have a running backend at localhost:8000
Could not extract text from PDF The PDF is a scanned image — each "page" is a JPEG embedded in PDF. pypdf can only read text layers Use a PDF you exported from Word, Google Docs, or a digital source. Avoid resume templates that export as images
Groq API 401 Unauthorized GROQ_API_KEY in .env is missing, misspelled, or the key has been revoked Log in to console.groq.com, generate a new key, paste it into .env, and restart uvicorn
Module 'groq' has no attribute 'AsyncGroq' Outdated version of the Groq SDK installed — AsyncGroq was added in a later release Run pip install --upgrade groq in your virtual environment and restart the server
Port 8000 already in use Another process (or a previous uvicorn session) is still bound to port 8000 Either kill the process (lsof -ti:8000 | xargs kill on Mac/Linux, Task Manager on Windows) or start on a different port: uvicorn main:app --reload --port 8001 — then update BASE_URL in js/api.js to match
sqlite3.OperationalError: no such table Base.metadata.create_all() did not run, so the SQLite file exists but has no tables Confirm that main.py calls Base.metadata.create_all(bind=engine) before the app starts. Delete job_copilot.db and restart uvicorn — it will be recreated cleanly
401 on every request after login The JWT has expired, or SECRET_KEY in .env changed between sessions, invalidating all existing tokens Open browser DevTools → Application → Local Storage → delete all entries for localhost:3000. Refresh and log in again
PDF parsed as empty string The PDF has copy-protection enabled, or all content is in embedded images (image-only PDF) Try a different PDF. You can test by opening the PDF and attempting to select and copy text — if you cannot select any text, pypdf cannot read it either
ES module error / import fails Opened index.html directly via the file:// protocol instead of through the HTTP server Always use http://localhost:3000. Verify the frontend server is running: python -m http.server 3000 in the frontend/ folder
Generation hangs indefinitely A Groq API request timed out or the rate limit was hit and no error was surfaced Check the backend terminal — you will see the exception there. Add a timeout to your AsyncGroq client calls: client = AsyncGroq(api_key=..., timeout=60)
Tip

The backend terminal is your best debugging tool. Every unhandled exception from a FastAPI route is printed there in full, including the Python traceback. Always check the terminal before looking at the browser console when something goes wrong.

WHY two separate servers instead of FastAPI serving the HTML

Separating frontend and backend into two processes mirrors how production works: a CDN or Nginx serves the static files; the API server handles only data. FastAPI can serve static files via StaticFiles, but mixing them creates a coupling where the Python process must stay up for the frontend to load at all. Two processes also means you can restart the backend (when you change Python code) without interrupting the frontend server — the browser just shows a stale page until the API comes back.
