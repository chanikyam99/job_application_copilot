Section 02

Features — Already Added

3 features that were in the capstone spec but missing from the codebase. All have been added directly to frontend/application.html. This page explains each one.

✅ Already in application.html — nothing to re-do

These additions are already in the repo. Read this page to understand what's there and where to find it if you need to tweak anything on the other laptop.

1 "Generate Kit" button when no draft exists

File: frontend/application.html

Why it was missing: If you navigate to application.html?id=X and no draft has been generated yet (e.g., the pipeline failed on first run), the 4 tabs were empty and there was no way to trigger generation. The POST /applications/{id}/generate endpoint existed on the backend but was never called from this page.

What was added — HTML banner (placed above the tabs):

frontend/application.html — no-draft banner HTML html 
<!-- ADDED: No-draft banner — shown when application exists but kit hasn't been generated yet -->
<div id="no-draft-banner" class="hidden"
     style="background:#fffbeb; border:1px solid #fcd34d; border-radius:12px;
            padding:20px 24px; margin-bottom:24px; display:flex;
            align-items:center; justify-content:space-between; flex-wrap:wrap; gap:12px;">
  <div>
    <div style="font-weight:600; color:#78350f;">AI kit not generated yet</div>
    <div style="font-size:0.875rem; color:#92400e; margin-top:4px;">
      Click "Generate Kit" to run all 4 agents (~20–30 seconds).
    </div>
  </div>
  <button class="btn btn-primary" id="generate-kit-btn">✨ Generate Kit</button>
</div>

What was added — JS logic (inside the script tag):

frontend/application.html — generate kit JS js 
// In loadApp() — show/hide banner based on draft existence
if (appData.draft) {
  renderAllTabs(appData.draft);
  document.getElementById('no-draft-banner').classList.add('hidden');
} else {
  // ADDED: show banner with Generate button when draft doesn't exist yet
  document.getElementById('no-draft-banner').classList.remove('hidden');
}

// ── ADDED: Generate Kit button event listener ──
document.getElementById('generate-kit-btn').addEventListener('click', async () => {
  const btn = document.getElementById('generate-kit-btn');
  btn.disabled  = true;
  btn.innerHTML = '<span class="spinner"></span> Running agents…';
  try {
    await api.post(`/applications/${appId}/generate`, {});
    // Reload to get the fresh draft
    appData = await api.get(`/applications/${appId}`);
    if (appData.draft) {
      renderAllTabs(appData.draft);
      document.getElementById('no-draft-banner').classList.add('hidden');
      toast('Kit generated!', 'success');
    }
  } catch (err) {
    toast(err.message, 'error');
    btn.disabled    = false;
    btn.textContent = '✨ Generate Kit';
  }
});

3 Skills to Emphasise + Key JD Keywords displayed

File: frontend/application.html

Why it was missing: The backend's Fit Analyst agent already returns skills_to_emphasize and key_keywords in its JSON output. The renderFit() function only read matching_requirements, missing_requirements, and overall_summary — the other two fields were silently ignored.

What was added — HTML (inside the fit tab, after the summary div):

frontend/application.html — skills + keywords HTML html 
<!-- ADDED: skills_to_emphasize + key_keywords (returned by backend but not displayed before) -->
<div id="fit-extra" class="hidden" style="margin-top:20px;">
  <div style="font-size:0.8rem; font-weight:600; color:#1d4ed8; margin-bottom:8px;">
    💡 Skills to Emphasise
  </div>
  <div id="fit-skills" style="display:flex; flex-wrap:wrap; gap:8px; margin-bottom:16px;"></div>
  <div style="font-size:0.8rem; font-weight:600; color:#7c3aed; margin-bottom:8px;">
    🔑 Key JD Keywords
  </div>
  <div id="fit-keywords" style="display:flex; flex-wrap:wrap; gap:8px;"></div>
</div>

What was added — JS (appended to the renderFit() function):

frontend/application.html — renderFit additions js 
// ADDED: render skills_to_emphasize and key_keywords
// (were generated by backend but never displayed)
const skills   = fit.skills_to_emphasize || [];
const keywords = fit.key_keywords || [];
if (skills.length || keywords.length) {
  document.getElementById('fit-extra').classList.remove('hidden');
  document.getElementById('fit-skills').innerHTML = skills.map(s =>
    `<span style="background:#eff6ff; color:#1d4ed8; padding:4px 12px;
                  border-radius:100px; font-size:0.8rem;">${s}</span>`
  ).join('');
  document.getElementById('fit-keywords').innerHTML = keywords.map(k =>
    `<span style="background:#f5f3ff; color:#6d28d9; padding:4px 12px;
                  border-radius:100px; font-size:0.8rem;">${k}</span>`
  ).join('');
}
WHY show skills and keywords?

The whole point of the Fit Analyst agent is to tell the user what to emphasise in the rewrite. Showing skills_to_emphasize and key_keywords in the UI gives the user actionable context — they can see what the resume rewrite agent focused on and manually tweak bullets if needed. The data was already being generated and stored; it just wasn't surfaced.

Verify the Features

  1. Open an application that has no draft → the amber banner "AI kit not generated yet" should appear with a "✨ Generate Kit" button → click it → tabs should populate.
  2. Open an application that has a draft → open the Fit Analysis tab → you should see a "↺ Regenerate" button in the top-right → click it → score ring should animate to the new score.
  3. On the same Fit Analysis tab, scroll down → you should see blue "Skills to Emphasise" chips and purple "Key JD Keywords" chips below the summary paragraph.
