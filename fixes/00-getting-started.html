Section 00 — Start Here

Get Started on the New Laptop

Copy the project across, create the virtual environment, set your API keys, and get both servers running. Do this before anything else.

⚠ Read this page top to bottom before typing any command

Steps 1 → 6 must be done in order. Skipping ahead (e.g. running uvicorn before installing packages) causes confusing errors that look unrelated to the real problem.

1 Copy the Project Folder

You need the full project folder on the new laptop. Use whichever method is easiest:

MethodHowWhen to use
USB / external drive Copy the entire Job Application Copilot folder to the drive, paste on new laptop Quickest if you have a drive handy
GitHub (recommended) Push on old laptop (Task 3 in section 03), then git clone <url> on new laptop Best for submission — you get a clean repo without venv/ or .db files
Google Drive / OneDrive Zip and upload, download and unzip on new laptop Works if you don't have a drive and haven't pushed to GitHub yet
Never copy the venv/ folder

Virtual environments are machine-specific — the binaries inside are compiled for the exact OS and Python version on the original machine. Always create a fresh venv on the new laptop (Step 3 below). If you copied it accidentally, delete the backend/venv/ folder before continuing.

2 Verify Python Is Installed

Open a terminal (PowerShell on Windows, Terminal on Mac) and run:

terminal bash 
python --version
# or on some systems:
python3 --version

You need Python 3.10 or higher. If Python is not installed, download it from python.org — use the installer, and tick "Add Python to PATH" during setup. After installing, close and reopen the terminal.

3 Create the Virtual Environment

Navigate into the backend/ folder and create a fresh venv:

terminal — navigate to backend/ first bash 
# Replace the path with wherever you copied the project
cd "C:\Users\YourName\Downloads\Job Application Copilot\Job Application Copilot\backend"

# Create a new virtual environment
python -m venv venv

Then activate it. The command is different on Windows vs Mac:

terminal — Windows (PowerShell) bash 
venv\Scripts\activate
terminal — Mac / Linux bash 
source venv/bin/activate

After activating, your prompt should start with (venv). Every terminal command in this guide assumes the venv is active. If you open a new terminal window, you must activate it again.

⚠ Windows execution policy error?

If you see "running scripts is disabled on this system", run this once in PowerShell as Administrator:
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
Then try activating again.

4 Install Packages

With the venv active, install all dependencies from requirements.txt:

terminal — from backend/ with venv active bash 
pip install -r requirements.txt

This installs FastAPI, SQLAlchemy, Groq SDK, pypdf, python-docx and everything else. It will take 1–3 minutes depending on internet speed. You should see a long list of "Successfully installed …" lines at the end.

⚠ pip not found?

Try python -m pip install -r requirements.txt instead. On some Windows setups pip is not on the PATH but python -m pip always works.

5 Create Your .env File

The project needs a backend/.env file with your real API keys. The repo contains .env.example — copy it and fill in your values:

terminal — from backend/ bash 
# Windows PowerShell:
copy .env.example .env

# Mac / Linux:
cp .env.example .env

Now open backend/.env in any text editor and fill in the two real values:

backend/.env — fill in your real values bash 
SECRET_KEY=paste-any-long-random-string-here-at-least-32-chars
ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=10080
GROQ_API_KEY=gsk_your_actual_groq_key_here
DATABASE_URL=sqlite:///./job_copilot.db
How to get a Groq API key

1. Go to console.groq.com → Sign up (free, no credit card needed)
2. Click API Keys in the left sidebar → Create API Key
3. Copy the key (starts with gsk_) → paste it as the value of GROQ_API_KEY
4. For SECRET_KEY use any random string — e.g. mash the keyboard for 40 chars: kj4h8FpQ2mNxR9vT1wL6aZ3cE7bY0dU5iO

Never commit .env to git

The .env file contains your real Groq API key. It is listed in .gitignore and must never be pushed to GitHub. The safe file to commit is .env.example (which has placeholder values). If you accidentally push your real key, rotate it immediately on console.groq.com.

6 Start the Backend

From backend/ with the venv active, run:

terminal — backend bash 
uvicorn main:app --reload --port 8000

You should see this output — keep this terminal open, do not close it:

expected output text 
INFO:     Will watch for changes in these directories: [...]
INFO:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)
INFO:     Started reloader process [...]
INFO:     Application startup complete.
⚠ Port 8000 already in use?

Another process is bound to port 8000. On Windows: open Task Manager → Details tab → find and end any python.exe processes. Or use a different port: uvicorn main:app --reload --port 8001 — then also update the BASE_URL in frontend/js/api.js from :8000 to :8001.

How to authorize in Swagger (test auth end-to-end)

  1. Click POST /auth/signup → Try it out → enter any email + password → Execute
  2. Click POST /auth/login → same credentials → Execute → copy the access_token from the response
  3. Click the Authorize button (top right of the page)
  4. In the popup, type Bearer then paste your token → click Authorize
  5. Now click GET /applications/ → Try it out → Execute — should return [] (empty list, not 401)

If all of that works, the backend is good. Proceed to Step 8.

8 Start the Frontend

Open a second terminal window (leave the backend running in the first). Navigate to the frontend/ folder:

terminal — second window, frontend only bash 
cd "C:\Users\YourName\Downloads\Job Application Copilot\Job Application Copilot\frontend"

python -m http.server 3000

Open http://localhost:3000 in your browser. You should see the login/signup page.

Why not just open index.html directly?

Opening index.html via file:// in your browser causes CORS errors — the browser blocks JS module imports from file:// paths. The Python HTTP server serves everything over http://localhost which the browser treats like a real site. Always use the server.

9 Test the Full Flow

Walk through this once to confirm everything works before starting the submission tasks:

1
Sign up at http://localhost:3000

Click "Create Account", enter email + password (min 8 chars). You should be redirected to the dashboard automatically.

2
Create a new application

Click "+ New Application". Step 1: drag a text-based PDF onto the drop zone (must be a digitally created PDF, not a scanned image). Step 2: fill in job title, company, and paste a full job description. Click "Generate My Kit".

3
Wait for generation (~20–30 seconds)

Watch the backend terminal — you should see Groq API calls logged. Agents 2, 3, 4 run in parallel so the total time is ~30s not ~90s. You will be redirected to application.html when done.

4
Check all 4 tabs

Fit Analysis: score ring + green/red requirement tags. Resume: before/after diff view. Cover Letter: readable letter + Download .docx button. Interview Prep: 10 expandable Q&As.

5
Update the status dropdown

Change from "Not Applied" to "Applied". A "Saved ✓" toast should flash briefly. If it flashes, the status endpoint is working.

6
Download the cover letter

On the Cover Letter tab, click "Download .docx". A .docx file should appear in your Downloads folder. Open it in Word or Google Docs to confirm the text is there.

7
Test a Regenerate button

Click "↺ Regenerate" on any tab. You should see a "Regenerating…" toast, wait ~10–15 seconds, then see "Regenerated!" and fresh content. Open DevTools (F12) → Network tab — the call should return HTTP 200, not 400 or 422.

If all 7 steps pass, the core app is working. Move on to section 03 to finish the remaining submission tasks.

Common Errors & Fixes

ErrorRoot causeFix
CORS error in browser console Backend is not running — browser can't reach localhost:8000 Start uvicorn (Step 6) and keep that terminal open. CORS errors almost always mean "no backend", not an actual CORS config problem.
ModuleNotFoundError: groq / fastapi Packages not installed, or venv not activated Activate venv first (venv\Scripts\activate), then pip install -r requirements.txt
Groq 401 Unauthorized GROQ_API_KEY in .env is missing, wrong, or expired Go to console.groq.com → API Keys → create a new key → paste into backend/.env → restart uvicorn
Could not extract text from PDF The PDF is a scanned image — pypdf can only read text layers Use a PDF exported from Word, Google Docs, or any digital source. Test by selecting text in the PDF — if you can't select, pypdf can't read it either.
sqlite3.OperationalError: no such table Database file exists but tables weren't created Delete backend/job_copilot.db and restart uvicorn — main.py calls Base.metadata.create_all() on startup which recreates tables.
401 on every request after login JWT expired, or SECRET_KEY changed between sessions Open DevTools → Application → Local Storage → delete all entries for localhost:3000. Refresh and log in again.
Port 8000 already in use Previous uvicorn session still running Windows: Task Manager → Details → kill python.exe. Or run uvicorn on port 8001 and update BASE_URL in frontend/js/api.js.
Page loads but JS errors / blank tabs Frontend opened via file:// not http://localhost:3000 Always serve via python -m http.server 3000 from the frontend/ folder. Never double-click the HTML file directly.
Generation hangs indefinitely Groq API timeout or rate limit hit Check the backend terminal for the Python traceback. If it's a rate limit, wait 60 seconds and try again. Groq free tier resets quickly.
