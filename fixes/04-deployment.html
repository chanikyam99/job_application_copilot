Section 04

Cloud Deployment

Deploy the FastAPI backend on Render with PostgreSQL, and serve the frontend from Vercel — fully live on the internet in under 30 minutes.

Code changes already made

The backend already has a Procfile, psycopg2-binary in requirements.txt, env-aware CORS, a fixed migrations/env.py, and a config.js that auto-detects localhost vs production. You do NOT need to add any new code — just follow the steps below.

🖥️ Render (Backend)

Runs the FastAPI process. Free tier available. Auto-deploys on every GitHub push. PostgreSQL add-on replaces SQLite.

🌐 Vercel (Frontend)

Serves the four static HTML pages. Free forever for static sites. Drag-and-drop deploy — no CLI or build step needed.

WHY PostgreSQL instead of SQLite in production

Render's file system is ephemeral — it resets on every deploy. A SQLite .db file would be wiped every time you push new code. PostgreSQL is a managed external service that persists independently of your deploys.

1 Push to GitHub First

Render connects to your GitHub repository. Do this before setting up Render.

terminal — project root bash 
git add .
git commit -m "add deployment config — Procfile, config.js, psycopg2"
git push -u origin main
Never commit backend/.env

Confirm backend/.env is in your .gitignore before pushing. Your Groq API key must not appear in the repository. The .env.example file (no real values) is safe to commit.

2 Deploy Backend on Render

  1. Go to dashboard.render.com → sign up with GitHub
  2. Click New + → Web Service
  3. Connect your GitHub repository
  4. Fill in these settings:
SettingValue
Namejob-copilot-api (or any name)
Root Directorybackend
EnvironmentPython 3
Build Commandpip install -r requirements.txt
Start Commanduvicorn main:app --host 0.0.0.0 --port $PORT
Instance TypeFree (for development/demo)

Do NOT click Deploy yet — add environment variables first (Step 4).

3 Add PostgreSQL Database

  1. On the Render dashboard, click New + → PostgreSQL
  2. Name it job-copilot-db → choose Free plan → click Create Database
  3. After creation, click the database → find Internal Database URL → copy it
Internal vs External URL

Use the Internal Database URL — traffic stays inside Render's network (faster). The External URL is only for connecting from your local machine to debug the production DB.

4 Set Environment Variables on Render

Go to your Web Service → Environment tab → add each variable:

KeyValue
DATABASE_URL The Internal Database URL from Step 3 (starts with postgresql://)
GROQ_API_KEY Your key from console.groq.com
SECRET_KEY Any random 32+ character string. Generate one:
python -c "import secrets; print(secrets.token_hex(32))"
ALLOWED_ORIGINS Set to * for now — update to your Vercel URL after Step 7

Click Save Changes, then click Deploy. Wait ~3 minutes for the first build.

5 Run Database Migration

After the first successful deploy, open Render Shell (top-right of your Web Service page) and run:

Render Shell bash 
alembic upgrade head

You should see output ending with Running upgrade ... -> initial schema. This creates the users, applications, and drafts tables in PostgreSQL.

6 Verify the Backend is Live

Render shows your service URL at the top of the dashboard (e.g. https://job-copilot-api.onrender.com).

browser or curl bash 
# Should return {"status":"ok","docs":"/docs"}
curl https://your-app.onrender.com/

# Visit Swagger UI — confirms all routes are registered
# https://your-app.onrender.com/docs
Free tier cold starts

On Render's free tier, the service spins down after 15 minutes of inactivity. The first request after inactivity takes ~30–60 seconds to wake up. This is expected — paid tiers eliminate cold starts.

7 Update config.js with Your Render URL

Open frontend/js/config.js and replace the placeholder:

frontend/js/config.js js 
window.BACKEND_URL = (
  location.hostname === 'localhost' ||
  location.hostname === '127.0.0.1'  ||
  location.hostname === ''
)
  ? 'http://localhost:8000'
  : 'https://job-copilot-api.onrender.com'; // ← your actual Render URL
terminal bash 
git add frontend/js/config.js
git commit -m "set production backend URL"
git push

8 Deploy Frontend on Vercel

  1. Go to vercel.com → sign in with GitHub → click Add New… → Project
  2. Import your GitHub repository
  3. Set Root Directory to frontend (click Edit → type frontend → Done)
  4. Leave Framework Preset as Other, leave everything else as default
  5. Click Deploy — Vercel builds in ~30 seconds and gives you a URL like https://job-copilot.vercel.app
  6. Every future git push automatically redeploys — no extra steps needed

9 Lock Down CORS

Now that you have your Vercel URL, go back to Render → your Web Service → Environment → update ALLOWED_ORIGINS:

Render — ALLOWED_ORIGINS value text 
https://your-app.vercel.app

Save and redeploy. The backend will now only accept requests from your Vercel domain.

Common Deployment Errors

ErrorRoot CauseFix
Build fails: No module named psycopg2 psycopg2-binary not in requirements.txt Confirm psycopg2-binary==2.9.9 is in backend/requirements.txt and push again
500 on every request Missing or wrong DATABASE_URL Check Render → Environment tab. Paste the Internal Database URL exactly
relation "users" does not exist Alembic migration was not run Open Render Shell → run alembic upgrade head
CORS error in browser ALLOWED_ORIGINS doesn't match Vercel domain Set exactly https://your-app.netlify.app (no trailing slash). Redeploy.
Frontend still calls localhost:8000 config.js has placeholder URL Update with real Render URL, commit, and re-drop frontend folder on Vercel
Swagger shows no routes Root Directory not set to backend Render Settings → Root Directory → backend → Manual Deploy
