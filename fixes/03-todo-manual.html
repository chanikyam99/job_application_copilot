1 Resume PDF Download — Backend Endpoint

Why: The spec says "Download buttons: cover letter as .docx, resume as PDF." Cover letter is done. Resume download is not.

What to do: Add one endpoint to backend/routers/applications_router.py. The simplest approach returns the rewritten resume as a plain-text file (no PDF generation library needed). Add it right after the cover-letter download endpoint.

backend/routers/applications_router.py — add after download/cover-letter endpoint python 
@router.get("/{app_id}/download/resume")
def download_resume(
    app_id: int,
    current_user: models.User = Depends(auth.get_current_user),
    db: Session = Depends(get_db)
):
    """Returns the rewritten resume as a downloadable .txt file.
    Plain text is the safest format — no PDF generation library needed.
    Users can paste it into any word processor and format as needed."""
    application = db.query(models.Application).filter(
        models.Application.id == app_id,
        models.Application.user_id == current_user.id
    ).first()

    if not application or not application.draft or not application.draft.resume_rewrite:
        raise HTTPException(status_code=404, detail="Resume rewrite not generated yet")

    rewrite_data = json.loads(application.draft.resume_rewrite)
    resume_text  = rewrite_data.get("text", application.original_resume)

    safe = lambda s: "".join(c for c in s if c.isalnum() or c in " _-")[:30]
    filename = f"resume_{safe(application.company)}_{safe(application.job_title)}.txt".replace(" ", "_")

    return Response(
        content=resume_text.encode("utf-8"),
        media_type="text/plain; charset=utf-8",
        headers={"Content-Disposition": f'attachment; filename="{filename}"'}
    )

2 Alembic Migrations — Run These Commands

Why: The capstone submission requires "an Alembic migrations folder if you used a relational DB." alembic is already in requirements.txt but was never initialised.

Run these commands from inside the backend/ folder (with venv activated):

terminal — from backend/ with venv active bash 
# 1. Initialise Alembic — creates alembic.ini and migrations/ folder
alembic init migrations

# 2. Open migrations/env.py and find this line:
#    target_metadata = None
# Replace it with:
#    from database import Base
#    target_metadata = Base.metadata

# 3. In alembic.ini, find:
#    sqlalchemy.url = driver://user:pass@localhost/dbname
# Replace with:
#    sqlalchemy.url = sqlite:///./job_copilot.db

# 4. Generate the first migration from your current models
alembic revision --autogenerate -m "initial schema"

# 5. Apply it (creates the tables — same as Base.metadata.create_all)
alembic upgrade head
⚠ env.py edit is required

Without editing migrations/env.py to import Base.metadata, the autogenerate command won't detect any models and will create an empty migration. The two lines to add/change are clearly marked in the commands above.

After running these commands, commit everything:

terminal bash 
git add alembic.ini migrations/
git commit -m "add alembic migrations for initial schema"

3 GitHub Repository — Create, Commit & Push

Why: The submission requires either a live URL or a GitHub repo. A GitHub repo is simpler and fully accepted. You need this before deploying to Vercel (Task 4).

Step 3.1 — Create a .gitignore file first

Create a file called .gitignore at the project root (same level as backend/ and frontend/). This tells git which files to skip. Do this before running any git add command.

.gitignore — create this file at the project root text 
# Secrets — never commit these
backend/.env

# Virtual environment — machine-specific, recreated with pip install
backend/venv/

# SQLite database — contains real user data, not source code
backend/*.db
backend/*.db-shm
backend/*.db-wal

# Python bytecode — auto-generated, not source code
**/__pycache__/
*.pyc
*.pyo

# OS files
.DS_Store
Thumbs.db
Never commit backend/.env

Your .env contains your real Groq API key. If you push it to a public repo, bots scrape GitHub within minutes and steal the key. The safe file is .env.example (placeholder values) — that one is fine to commit and is already in the repo.

Step 3.2 — What gets committed (and what doesn't)

File / FolderCommitted?Why
backend/*.pyYesAll Python source files — the actual code
backend/requirements.txtYesRequired so anyone can recreate the venv

backend/agents/, routers/, utils/YesAll subfolders with Python files
frontend/*.html, css/, js/YesAll frontend files
guide/, fixes/YesDocumentation — useful to include
REQUIREMENTS.mdYesProject spec — fine to include

    https://github.com/YOUR_USERNAME/job-application-copilot.git

Open a terminal at the project root (the folder that contains both backend/ and frontend/):

⚠ git not found on Windows?

Download and install Git from git-scm.com → use the default installer settings. After installing, close and reopen your terminal. Then run git --version to confirm it works.

Step 3.5 — Connect to GitHub and push

Replace YOUR_USERNAME with your actual GitHub username:

terminal — connect remote and push bash 
# Connect your local repo to GitHub
git remote add origin https://github.com/YOUR_USERNAME/job-application-copilot.git

# Rename the branch to 'main' (GitHub's default)
git branch -M main

# Push — the -u flag sets the upstream so future pushes just need 'git push'
git push -u origin main

GitHub will ask for your username and password. The password is NOT your GitHub account password — it's a Personal Access Token (PAT):

  1. On GitHub: click your profile photo → Settings → Developer settings (bottom of left sidebar) → Personal access tokens → Tokens (classic)
  2. Click Generate new token (classic)
  3. Set expiration to 90 days, tick the repo scope checkbox
  4. Click Generate → copy the token (starts with ghp_)
  5. Paste it as the password when git prompts you

4 Frontend Deployment — Vercel (Optional but Easy)

Step 4.2 — Deploy to Vercel

  1. Go to vercel.com → click Sign Up → choose Continue with GitHub. Authorize Vercel to access your GitHub.
  2. You land on the Vercel dashboard. Click Add New… → Project.
  3. Under "Import Git Repository", find job-application-copilot in the list → click Import.
  4. On the configuration screen:
    • Framework Preset: leave as Other (Vercel auto-detects static HTML)
    • Root Directory: click Edit → type frontend → click Done. This is the most important setting — without it Vercel tries to deploy the whole repo including backend.
    • Leave everything else as default.
  5. Click Deploy. Vercel builds in ~30 seconds.
  6. You get a URL: https://job-application-copilot-abc123.vercel.app — click it to verify the login page loads.
  7. Copy this URL and use it as your frontend submission link.

Step 4.3 — Redeploying after changes

Vercel watches your GitHub repo automatically. Every time you git push, Vercel rebuilds and redeploys within ~30 seconds. You don't need to do anything in the Vercel dashboard after the first deploy.

terminal — update Vercel by just pushing to GitHub bash 
# Make your changes, then:
git add .
git commit -m "update frontend"
git push
# Vercel automatically picks up the push and redeploys — no extra steps
⚠ Backend deployment needs Postgres, not SQLite

If you also want to deploy the backend (to get a live API that the Vercel frontend can call), you must switch from SQLite to Postgres. Render's free tier uses an ephemeral filesystem — the .db file is wiped on every redeploy. This is significant extra work and not needed for the capstone submission. 7 JD URL Scraping — Stretch Feature (Do Last)

Why: The spec says "JD paste box; bonus: paste a LinkedIn URL and scrape with requests + beautifulsoup4." Both libraries are already installed.

Only attempt this if tasks 1–6 are complete. LinkedIn actively blocks scrapers — a simpler approach is to scrape generic job pages or just show a fallback "URL scraping failed, please paste the JD instead."

Add this utility to backend/utils/pdf_parser.py (or a new backend/utils/jd_scraper.py):

backend/utils/jd_scraper.py — create this file python 
import requests
from bs4 import BeautifulSoup


def scrape_jd_from_url(url: str) -> str:
    """
    Attempts to extract job description text from a URL.
    Returns the extracted text, or raises an exception if scraping fails.
    Works for most generic job pages; LinkedIn often blocks this.
    """
    headers = {
        "User-Agent": (
            "Mozilla/5.0 (Windows NT 10.0; Win64; x64) "
            "AppleWebKit/537.36 (KHTML, like Gecko) "
            "Chrome/120.0.0.0 Safari/537.36"
        )
    }
    response = requests.get(url, headers=headers, timeout=10)
    response.raise_for_status()

    soup = BeautifulSoup(response.text, "html.parser")

    # Remove navigation, headers, footers, scripts, styles
    for tag in soup(["script", "style", "nav", "header", "footer", "aside"]):
        tag.decompose()

    # Try common job description containers first
    for selector in [
        "[data-testid='job-details']",   # LinkedIn (may not work)
        ".job-description",
        ".job-details",
        "#job-description",
        "article",
        "main",
    ]:
        el = soup.select_one(selector)
        if el:
            text = el.get_text(separator="\n", strip=True)
            if len(text) > 200:
                return text

    # Fallback: extract all paragraph text
    text = soup.get_text(separator="\n", strip=True)
    return text[:5000]  # Limit to first 5000 chars

Add a backend endpoint to applications_router.py:

backend/routers/applications_router.py — add near the top python 
from utils.jd_scraper import scrape_jd_from_url

class ScrapeRequest(BaseModel):  # add to schemas.py instead if preferred
    url: str

@router.post("/scrape-jd")
def scrape_jd(
    req: ScrapeRequest,
    current_user: models.User = Depends(auth.get_current_user)
):
    """Scrapes JD text from a URL. Falls back gracefully if scraping fails."""
    from pydantic import BaseModel
    try:
        text = scrape_jd_from_url(req.url)
        return {"jd_text": text, "success": True}
    except Exception as e:
        raise HTTPException(
            status_code=400,
            detail=f"Could not scrape that URL: {str(e)}. Please paste the JD text manually."
        )
